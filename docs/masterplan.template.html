Product blueprint · v2 · cPanel-first, portable

One zip. Every part of a school, automated.

Pathshala runs admissions, academics, attendance, assessment, fees and accounting, HR and payroll, transport, hostel, library, inventory, communication, welfare, documents, alumni, events, governance, compliance, analytics and an AI assistant — for desktop, tablet and the guardian, student, teacher and driver apps. It installs itself on Namecheap cPanel and moves to a VPS later without a rewrite.

349 tables in 34 modules115+ automations5-year roadmap already in the schemaUpload zip → dashboard in ~5 min, zero cPanel clicksReact 19 · React Router SSR · Tailwind 4 · Node 22 + Express 5 · MySQL + Drizzle · Web Push · Cloudflare

Why schools switch to it

Every routine job a school pays people to remember — absent SMS, fee invoices, reminders, fines, result cards, payroll, bus alerts, TC eligibility — happens on its own and is visible in one activity log. Staff handle exceptions, not routine.

Why it runs on ৳3,000/year hosting

A single Node 22 process under Passenger serves the React Router SSR app, the API, the scheduler and the queue worker. Only pure-JS packages (bcryptjs, jimp, pdf-lib, SheetJS, mysql2), no cPanel cron needed, every long job chunked under 30 s, files in uploads/, nightly backups off-site, Cloudflare in front.

Why it will not need a rewrite

Schema-first (one definition file generates SQL, types and docs), events between modules instead of calls, custom fields and form/workflow builders for per-school needs, and hosting-specific code isolated in adapters.

Zero-touch on cPanel

Upload the zip, extract, open the domain. That is the whole install.

PHP is always present on cPanel, so a tiny install.php bootstraps the Node app: detects Node, creates the database (or falls back to SQLite), writes the Passenger config and cron, then hands over to the Node installer wizard, which seeds everything and self-tests.

Moving to a VPS later

  1. docker compose up (Postgres, Redis, MinIO, Chromium, api, web).
  2. Settings → Hosting → Export: one archive of database + files.
  3. Import on the VPS; change DB_URL and ADAPTERS.
  4. Point DNS. The guardian PWA keeps working on the same domain.

Updates

Settings → Hosting → Update downloads the signed release zip, swaps app/ atomically, runs migrations, restarts Passenger, keeps a 7-day rollback. Schools never open cPanel again.

Mechanism

Every section automated, one engine

Every write emits an event inside the same transaction. System handlers (always on), editable rules and scheduled jobs react. On shared hosting the engine lives inside the Passenger process with a request-driven heartbeat as the safety net.

Identity

Design system · the exercise book

Cool paper, ruled-line blue, margin red: the object every Bangladeshi student carries. One accent for actions, one red for problems, teal only for what the system did on its own. Every colour has a light and a dark value; schools may replace the accent with their brand.
